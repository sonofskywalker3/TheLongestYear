**Status:** APPROVED-IN-BRAINSTORM 2026-07-20 (user rulings inline); awaiting written-spec
review. Child of `2026-07-14-tly-0.12.0-owned-bundle-engine-design.md` (the parent spec's

**Slayer's rationale (user ruling):** each donation proves a COMPLETED eradication goal
that loop — TLY wipes `specificMonstersKilled` every reset, so trophies are re-earned
per loop, which also means NO uniqueness exclusions are needed (donating a one-time
reward is safe; the next loop hands it back). Coexists freely with vanilla Adventurer's —
zero item overlap, so the earlier "not both in one season" concern is moot.

## Non-object donation support (NEW mechanic, required by Slayer's)

Stardew 1.6 bundle DATA already accepts qualified ids (`(W)…`, `(H)…`); what blocks
weapon/hat donation is the CC menu code assuming Object donations. Ship a small Harmony
patch cluster on `JunimoNoteMenu`/`Bundle` covering: (1) inventory highlight (weapons/
hats currently grey out), (2) the can-accept-item check, (3) donation consumption
bookkeeping. Rings are already Objects and need none of this.

**Risk containment (locked):** the patch cluster ships behind a config kill-switch
(`EnableNonObjectDonations`, default on) with a **rings-only fallback**: if the smoke
pass finds vanilla resistance, Slayer's degrades to the 5-ring pool (rings donate
today) instead of blocking the release. TLY-side consumers (catalog, DonationObserver,
rarity/JP resolution, season-goals rendering) must handle `(W)`/`(H)` ids wherever they
assume `(O)`.

## Tea (user ruling)

- **Green Tea** already enters bundles via the artisan pool (category −26) — verify in
  smoke, no code needed.
- **Tea Leaves** cannot enter via `Data/Crops` (tea bushes aren't crops); add a curated
  crop-pool additions knob (sibling of `SeasonalForageAdditions`): Tea Leaves joins the
  crops pool with Spring/Summer/Fall windows (bush harvest starts Spring 22 at the
  earliest — the existing season-gate clamp handles the rest via its pin).
- Four Seasons Sampler's reward (Tea Sapling x2) completes the tea loop.

## Vault — engine-owned +25% (parent spec, restated)

The four money bundles keep their structure, amounts +25%: 2,500→3,125g, 5,000→6,250g,
10,000→12,500g, 25,000→31,250g. `VaultBundleMap` derives indices from live BundleData
and keeps working unchanged. (0.13.0 tiers scale further.)

## Normal-bar baseline tuning

Target (parent spec, locked): **a very skilled player cannot finish in 1 loop.** All
dials live in `GameplayConfig.PoolTuning`; tuning happens in playtest against that bar.
Plan-scope tuning levers: authored-bundle frequency in room pools (position-pool
weights), Slayer's shown/required counts, large-quantity forage chance/range, quality-ask
chances, Vault +25%. Also in scope as a flavor lever: an optional flowers sub-pool for
the Garden bundle (Plan-2 note: it currently re-rolls from ALL crops).

## Carried constraints from Plans 1–2 (do not violate)

- Authored bundle names are STABLE, unique, and **slash-free** (Uniquify runs before the
  writer's sanitize — a slashed authored name would collide post-sanitize).
- Determinism: every roll derives from the loop seed + stable salts; authored pools are
  ordinal-ordered; write-key space stays invariant (authored bundles are candidates
  WITHIN existing room positions — they never add/remove positions).
- Vault slots untouched except the +25% amounts. Pre-engine saves keep the legacy path
  until their next reset. Core stays pure; the exclude-list/marker vetting applies to
  authored pools exactly as to derived ones.

## Testing

- Unit: authored-pool derivation (artifacts/books/saplings/geode-contents from synthetic
  data, vetting incl. banana/mango + island/Qi books), Slayer's roll shape, Vault +25%
  math, tea additions, name slash-freedom guard.
- Smoke (throwaway save, per the established unattended loop — `tly_reset`, never
  `tly_failreset`): authored bundles appear across several generated boards
  (`tly_genbundles` over multiple loop numbers), **ring donation live-verified, then
  weapon/hat donation live-verified with the patch cluster** (fallback exercised with
  the kill-switch off), Vault shows +25% amounts, full donate/gate cycle on an authored
  bundle, season-goals + weekly themes render authored asks, 0 errors.
- SVE spot-check rides the next natural SVE session (no new SVE-specific mechanics here;
  sapling/book pools are data-derived and marker/exclude-vetted like everything else).
