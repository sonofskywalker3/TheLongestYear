# Keep Wallet Items and Stardrops across a reset

**Date:** 2026-08-27
**Status:** approved in brainstorm (Jeff), not yet planned
**Companion:** `2026-08-27-keep-power-books-design.md` (shipped 0.16.17). This spec extends the
same machinery to the remaining "power granted by an in-world source" class.

## Problem

The rewind wipes every wallet item (Rusty Key, Skull Key, Club Card, Special Charm, Dark Talisman,
Magic Ink, Dwarvish Translation Guide, Town Key, Magnifying Glass) and every Stardrop (+34 max
energy each, seven sources). Jeff's ruling 2026-08-27: **keepable, bought with JP at the Junimo
Shrine, per item**, the same shape as the book keeps.

Two things found while designing that the build must handle:

1. **Bear's Knowledge and Spring Onion Mastery already survive for free.** `Data/Powers` grants
   them on `SEEN_EVENT 2120303` (Woods, the bear) and `SEEN_EVENT 3910979` (Forest, Jas and
   Vincent), not on a mail flag. `FarmerReset` re-seeds `eventsSeen` from the cross-loop "seen
   ever" set, and neither event grants mail/recipe/quest so `ReplayableEventScan` does not flag
   it; both powers therefore come back every loop unpaid. Ruling: **make them paid like the rest.**
2. **A count-based Stardrop keep would be farmable.** The game records how many Stardrops were
   eaten (`maxStamina`), not which. If keeps were "1st .. 7th Stardrop", a player could take the
   Fair Stardrop every loop and climb the chain. Ruling: **gate per source, and a kept Stardrop
   keeps its source marked as claimed** so that source cannot pay out again.

## Design

### Rows

Eighteen `UpgradeCategory.Carryover` rows generated by two new generators in
`UpgradeCatalogGenerators`, appended after `CarryoverBookKeeps()`:

- `CarryoverWalletKeeps()`: eleven rows, id `keep_wallet_<slug>`.
- `CarryoverStardropKeeps()`: seven rows, id `keep_stardrop_<source>`.

A single Core table, `WalletKeepTable` (slug, kind, marker(s), cost, prerequisite, i18n name
key), is shared by the generators and `RunBaselineBuilder`, mirroring `BookKeepTable`.

### Names and descriptions

New i18n keys in `i18n/default.json`, one pair per row (`upgrade.keep_wallet_<slug>.name` /
`.desc`, `upgrade.keep_stardrop_<source>.name` / `.desc`). Names: "Keep Rusty Key", "Keep Bear's
Knowledge", "Keep Stardrop (Fair)" and so on. Descriptions say what comes back, e.g. "Start each
loop with the Skull Key in your wallet and the Skull Cavern door already open." The Powers-screen
strings live in the game's `Strings\1_6_Strings`, but the seven Stardrop rows have no vanilla
name, so all eighteen use mod i18n for consistency (translators get one file). No `item:` tokens.

### Reach

`RunReachRequirement.Parse` accepts two new keyed metrics, threshold 1:

- `mail:<flag>`: `RunReachEvaluator` answers with `Game1.MasterPlayer.mailReceived.Contains(flag)
  || Game1.player.mailReceived.Contains(flag)` (covers the MasterPlayer-backed getters).
- `event:<id>`: `Game1.player.eventsSeen.Contains(id)`.

Plus one bare metric `stardrop_mines`: `mailReceived.Contains("CF_Mines") ||
chestConsumedMineLevels.GetValueOrDefault(100)`.

### Baseline and reset

`RunBaseline` gains:

- `KeptMailFlags : IReadOnlyList<string>` (default empty). For each owned wallet or Stardrop row
  the table's marker(s): the wallet flag, or the CF_/museumComplete flag. `keep_wallet_skullkey`
  contributes both `HasSkullKey` and `HasUnlockedSkullDoor`. `keep_stardrop_mines` contributes
  `CF_Mines` (vanilla accepts it as "chest taken", so the chest stays closed).
- `KeptEventIds : IReadOnlyList<string>` (default empty). `2120303` and/or `3910979` when bought.
- `KeptStardropCount : int` (default 0). Number of owned `keep_stardrop_*` rows.

`RunBaselineBuilder.Build` fills them from owned row ids via `WalletKeepTable`.

`FarmerReset.Apply`, after the existing wipes:

1. `mailReceived.Add(flag)` for each `KeptMailFlags` entry (after `mailReceived.Clear()`).
2. `eventsSeen.Add(id)` for each `KeptEventIds` entry (after the re-seed).
3. `maxStamina = 270 + 34 * KeptStardropCount` (replaces the bare 270), then vitals to full.
4. Summary log gains `wallet=[...]`, `events=[...]`, `stardrops=N`.

### Closing the free Bear / Spring Onion keep

`EventGatingTables.Default` adds `2120303` and `3910979` to `ReplayableEventIds`. The re-seed
then skips them, so an unbought power's scene (and the power) must be earned again next loop.
A bought one is re-added by step 2 above, which is exactly what grants the power. The events'
own preconditions (secret note 23 for the bear, the Forest scene's day/weather) apply again each
loop as they would for a new player; that is the intended "earn it again" path.

### Edge cases, accepted as-is

- A Stardrop earned this loop but stashed uneaten: eating it next loop adds +34 on top of the
  kept +34, once. The source stays marked claimed, so it cannot repeat. Not built around.
- Kept `HasUnlockedSkullDoor` without the kept key cannot happen (one row sets both).
- Kept `museumComplete` with a wiped museum: the flag only gates the Stardrop reward and the
  "museum complete" dialogue; donations are governed by the netWorldState audit, unchanged.
- Multiplayer: out of scope, same as every other keep.

### Debug

`tly_wallet <flag|event:<id>|stardrop:<source>>` sets the marker as the game would (mail add,
eventsSeen add, or CF_ mail plus +34 stamina for a Stardrop). No args prints every marker in the
table with its current state. Lets the smoke run from the SMAPI console.

## Testing

Core (xunit):
- generators emit 11 + 7 rows, ids / costs / bands match the table, only Dark Talisman and Magic
  Ink carry prerequisites, every row is Carryover with the listed reach;
- `RunReachRequirement.Parse` handles `mail:X`, `event:N`, `stardrop_mines`;
- `RunBaselineBuilder` maps owned rows to `KeptMailFlags` / `KeptEventIds` /
  `KeptStardropCount`, Skull Key yields two flags, nothing owned yields empties and 0;
- `EventGatingTables.Default.IsReplayable("2120303")` and `("3910979")` are true;
- `KeepShopFilter` hides an unmet row and shows it once met;
- i18n guard passes with the 36 new keys.

Live (throwaway save, `tly_loadsave`): `tly_wallet HasSkullKey`, `tly_wallet stardrop:fair`,
`tly_wallet event:2120303`, `tly_addjp 2000`, buy `keep_wallet_skullkey` and
`keep_stardrop_fair` but NOT the bear, `tly_reset`; expect the reset log line to show
`wallet=[HasSkullKey,HasUnlockedSkullDoor,CF_Fair] events=[] stardrops=1`, `tly_wallet` to show
the Skull Key, door and CF_Fair set, max energy 304, and `2120303` absent from eventsSeen. Then
confirm the Fair Stardrop stall refuses (`CF_Fair`) on the next Fair.
