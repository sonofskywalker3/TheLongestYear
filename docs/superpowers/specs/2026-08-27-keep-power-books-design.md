# Keep Power Books across a reset

**Date:** 2026-08-27
**Status:** approved in brainstorm (Jeff), building
**Supersedes in part:** the 2026-07-10 ruling that every `Book_*` stat is wiped. The wipe stays;
kept books are re-granted from the run baseline after it.

## Problem

Every power granted by an in-world source is wiped on the rewind. `StatResetRules` is
wipe-by-default and its header names `Book_*` and `mastery_*` as the class it exists to stop
leaking. Jeff wants a deliberate, bought way for those powers to survive, starting with the
books. The brainstorm settled "per power" over "one big keep".

## Catalogue of power sources the reset touches

| Source | State | Decision |
|---|---|---|
| Power books (19 `Book_*` stats) | Binary flag per book, set by `Object.readBook`; a second read gives XP, so nothing stacks | **Keep, per book, bought at the shrine** (this spec) |
| Mastery | `MasteryExp`, `masteryLevelsSpent`, five `mastery_N` claims | Already Keep Mastery 1..5 (permanent floor, perks re-claimed at the pedestal). No change |
| Trinket slot | `trinketSlots`, set only by the Combat mastery claim | Rides on Keep Mastery. No change |
| Prize ticket ladder | `ticketPrizesClaimed` (rung), `specialOrderPrizeTickets` (board hand-out counter), `(O)PrizeTicket` items | Wiped as today. Tickets are items and can be stashed already. No change |
| Perfection perks | `farmPerfect`, `perfectionWaivers` | Unreachable inside one loop; ruled by the netWorldState audit. Out of scope |
| Wallet items, Stardrops (`mailReceived`) | Wiped today | Out of scope for this pass; flagged only |

`_bookFurniture` / `BookKit` in ModEntry are the mod's own Cookbook, Craftbook and Bundle Log
furniture. They are unrelated to vanilla power books and are not touched.

## Design

### Rows

Nineteen `UpgradeCategory.Carryover` rows, generated by `UpgradeCatalogGenerators.CarryoverBookKeeps()`
and appended after the mastery keeps. Id `keep_book_<slug>` where slug is the stat key after
`Book_`, lower-cased (`keep_book_speed`, `keep_book_speed2`, `keep_book_pricecatalogue`, ...).

Each row has `runReachRequirement: "book:<Book_Id>"`. `keep_book_speed2` has
`prerequisiteId: "keep_book_speed"`; every other row is standalone. Because
`KeepShopFilter.IsBuyable` hides rows whose reach is not met, a Fail night shows only the books
read that loop, never a wall of nineteen.

### Names and descriptions

`UpgradeDefinition.ResolveTokens` gains a second prefix, `item:<qualified id>`, resolved through
`Strings.ResolveItemName`, a provider injected like the translation provider. ModEntry wires it to
`ItemRegistry.GetDataOrErrorItem(id).DisplayName`; uninitialised it returns the id (loud, never a
crash), and the test fixture injects a dictionary. Rows use
`nameKey = "upgrade-tpl.keep-book.name"` ("Keep {{book}}") and
`descKey = "upgrade-tpl.keep-book.desc"` ("Start each loop with {{book}} already read. Its power
stays with you.") with `tokens["book"] = "item:(O)<Book_Id>"`.

### Reach

`RunReachRequirement.Parse` accepts the keyed-flag form for metric `book` (`book:Book_Speed`,
threshold 1). `RunReachEvaluator.Meets` answers `"book"` with `p.stats.Get(r.Key) != 0 ? 1 : 0`.

### Baseline and reset

- `RunBaseline.KeptBookStats : IReadOnlyList<string>` (default empty).
- `RunBaselineBuilder.Build` fills it with the stat key of every owned `keep_book_*` row, using
  a single table in Core (`BookKeepTable`: stat key, slug, cost, prerequisite) shared by the
  generator and the builder so the two can never drift.
- `FarmerReset.Apply` runs the existing `StatResetRules` wipe unchanged, then
  `p.stats.Set(key, 1)` for each kept key, and appends `books=[...]` to its summary log.
- `StatResetRules` header gains one paragraph: kept books are re-granted from the baseline
  after the wipe (same shape as `MasteryExp`), so the wipe-by-default rule is intact.

### Debug

`tly_readbook <Book_Id>` sets that stat to 1 (simulates reading the book). With no argument it
prints every `Book_*` key and value. Lets the smoke run from the SMAPI console.

## Testing

Core (xunit):
- generator emits 19 rows, ids and costs match the table, only `keep_book_speed2` has a
  prerequisite, every row is Carryover with a `book:` reach;
- `RunReachRequirement.Parse("book:Book_Speed")` yields metric `book`, key `Book_Speed`, threshold 1;
- `RunBaselineBuilder` maps owned rows to `KeptBookStats` and leaves it empty otherwise;
- `KeepShopFilter` hides a book row whose reach is unmet and shows it once met;
- `item:` tokens resolve through the provider; i18n guard passes with the two new keys.

Live (Rodger throwaway save, `tly_loadsave`): `tly_readbook Book_Speed`, `tly_addjp 1000`,
`tly_buyupgrade keep_book_speed`, `tly_reset`; expect `books=[Book_Speed]` in the FarmerReset
log line and `tly_readbook` printing `Book_Speed=1` with an unbought book at 0.

## Out of scope

Wallet items, Stardrops, mod-added books (unknown stat keys stay wiped), a "keep everything"
switch, any change to mastery or the prize ladder.
